1주차에 배운 리눅스 기본 조작을 **실제로 작업하는 순서**에 맞춰 살펴보겠습니다.

1. 명령이 어디로 전달되는지 이해하기 — 터미널과 셸

3. 파일과 디렉터리 다루기 — `mkdir`, `touch`, `cp`, `mv`, `rm`
4. 권한 읽고 바꾸기 — `chmod`, `sudo`, `chown`
5. 내용을 고치고 작업을 묶기 — `nano`, `vi`, 셸 스크립트

## 명령은 어떤 길을 거쳐 실행될까

터미널 창에 `ls`를 입력하면 결과가 바로 나오는 것처럼 보이지만, 그 사이에서는 두 프로그램이 일을 나눠 맡습니다.

```text
키보드 ──▶ 터미널 ──▶ 셸 ──▶ 운영체제
화면   ◀── 터미널 ◀── 셸 ◀── 실행 결과
```

- **터미널**은 입력을 받고 결과를 보여 주는 창입니다. Windows Terminal, macOS Terminal, MobaXterm처럼 겉모습은 달라도 맡은 일은 같습니다.
- **셸**은 터미널에서 넘어온 글자를 명령으로 해석하고 운영체제에 실행을 요청하는 프로그램입니다. `bash`, `zsh`, `sh` 등이 있습니다.

그래서 같은 터미널 창을 쓰더라도 그 안에서 돌아가는 셸이 바뀌면 쓸 수 있는 문법이나 읽어 들이는 설정 파일이 달라집니다. 내 계정에 기본으로 지정된 셸은 환경 변수 `SHELL`에 들어 있습니다.

```console
$ echo $SHELL
/bin/bash
```
> 프롬프트 끝의 기호로 권한을 구분할 수 있습니다. `$`는 일반 사용자, `#`는 **root**입니다.

## 입력을 줄여 주는 셸 기능

명령을 전부 손으로 치다 보면 오타가 나기 쉽습니다. 셸이 기본으로 제공하는 기능을 쓰면 입력량과 실수를 함께 줄일 수 있습니다.

| 하고 싶은 일 | 방법 |
| :--- | :--- |
| 명령어·경로 이름 마저 채우기 | 앞부분 입력 후 <kbd>Tab</kbd> (후보가 여러 개면 두 번) |
| 방금 쓴 명령 다시 불러오기 | <kbd>↑</kbd> / <kbd>↓</kbd> |
| 예전에 쓴 명령 검색하기 | <kbd>Ctrl</kbd>+<kbd>R</kbd> 후 기억나는 글자 입력 |
| 입력 기록 전체 보기 | `history` |
| 기록 속 특정 번호의 명령 다시 실행 | `!번호` (예: `!25`) |
| 화면 비우기 | `clear` 또는 <kbd>Ctrl</kbd>+<kbd>L</kbd> |

예를 들어 `cd Doc`까지만 입력하고 <kbd>Tab</kbd>을 누르면 `cd Documents/`로 완성됩니다. 실제로 있는 이름만 채워 주기 때문에 경로를 잘못 적는 일도 줄어듭니다.

## 확인하고, 둘러보고, 이동하기

디렉터리를 옮겨 다니며 작업할 때는 다음 세 명령을 한 묶음으로 씁니다.

| 순서 | 명령 | 이름의 유래 | 하는 일 |
| :---: | :--- | :--- | :--- |
| ① | `pwd` | **p**rint **w**orking **d**irectory | 현재 작업 디렉터리 경로 출력 |
| ② | `ls` | **l**i**s**t | 디렉터리 안의 항목 나열 |
| ③ | `cd` | **c**hange **d**irectory | 작업 디렉터리 변경 |

홈 디렉터리에서 `project`로 들어갔다가 다시 나오는 과정을 따라가 보면 다음과 같습니다.

```console
$ pwd                # 지금 어디인지 먼저 확인
/home/user
$ ls                 # 들어갈 디렉터리가 있는지 확인
notes.txt  project
$ cd project         # 이동
$ pwd                # 제대로 옮겨 왔는지 다시 확인
/home/user/project
$ cd ..              # 한 단계 위로 복귀
```

이동한 뒤 `pwd`로 한 번 더 확인하는 습관을 들이면 엉뚱한 위치에서 파일을 만들거나 지우는 실수를 막을 수 있습니다.

### `ls` 옵션은 글자마다 뜻이 있다

| 옵션 | 기억하는 법 | 추가로 보여 주는 것 |
| :--- | :--- | :--- |
| `-l` | **l**ong (길게) | 권한, 소유자, 크기, 수정 시각 |
| `-a` | **a**ll (전부) | `.`으로 시작하는 숨김 파일, `.`과 `..` |

옵션은 `ls -al`처럼 붙여 써도 되고 `ls -a -l`처럼 나눠 써도 결과가 같습니다. `-l`로 본 결과에서 각 줄의 첫 글자가 `d`면 디렉터리, `-`면 일반 파일이고, 그 뒤에 이어지는 글자들이 권한입니다. 권한을 읽는 법은 아래에서 따로 다룹니다.

### 자주 쓰는 경로 기호

경로에는 디렉터리 이름 대신 미리 약속된 기호를 쓸 수 있습니다.

| 기호 | 가리키는 곳 | 예 |
| :---: | :--- | :--- |
| `~` | 내 홈 디렉터리 | `cd ~` (그냥 `cd`만 입력해도 같음) |
| `.` | 현재 디렉터리 | `./hello.sh` |
| `..` | 한 단계 위 디렉터리 | `cd ..` |
| `-` | 직전에 있던 디렉터리 (`cd`에서만) | `cd -` |

`cd -`는 두 위치를 번갈아 오갈 때 편하고, 이동하면서 돌아간 경로를 출력해 줍니다.

```console
$ cd /var/log
$ cd -
/home/user
```

### 같은 곳을 가리키는 두 가지 방법

경로는 주소에 비유할 수 있습니다. **절대 경로**는 시·구·동부터 모두 적은 전체 주소처럼 최상위 `/`부터 적기 때문에 어디서 쓰든 같은 곳을 가리킵니다. **상대 경로**는 "여기서 한 칸 위로 올라가 옆 건물"처럼 현재 위치를 기준으로 적기 때문에 짧지만, 출발점이 바뀌면 도착지도 바뀝니다.

```text
/
└── home
    └── user          ← 홈 디렉터리 (~)
        ├── project   ← 지금 여기에 있다고 가정
        └── week2     ← 가고 싶은 곳
```

`/home/user/project`에서 `week2`로 가는 방법은 두 가지이고, 둘 중 어느 것을 실행해도 도착하는 곳은 같습니다.

```console
$ cd /home/user/week2   # 절대 경로: 현재 위치와 상관없이 항상 같은 곳
$ cd ../week2           # 상대 경로: 상위(user)로 올라간 뒤 week2로
```

## 파일을 만들고, 옮기고, 확인하기

파일 작업도 명령으로 할 수 있습니다. `mkdir -p`의 `-p`는 필요한 상위 디렉터리까지 함께 만든다는 뜻입니다.

| 명령 | 하는 일 | 예 |
| :--- | :--- | :--- |
| `mkdir` | 디렉터리 만들기 | `mkdir notes` |
| `touch` | 빈 파일 만들기 | `touch memo.txt` |
| `cp` | 파일 복사 | `cp memo.txt backup.txt` |
| `cp -r` | 디렉터리 복사 | `cp -r src/ dst/` |
| `mv` | 파일 이동 또는 이름 변경 | `mv old.txt new.txt` |
| `cat` | 파일 내용 출력 | `cat memo.txt` |
| `rm` | 파일 삭제 | `rm memo.txt` |

`touch`는 파일이 이미 있으면 내용을 지우는 대신 수정 시각을 갱신합니다. `>`는 파일 내용을 덮어쓰고, `>>`는 기존 내용 뒤에 이어 씁니다.

```bash
mkdir -p ~/study/week1
cd ~/study/week1
touch hello.txt
echo "첫 줄" > hello.txt
echo "둘째 줄" >> hello.txt
cat hello.txt
cp hello.txt backup.txt
mv backup.txt hello.bak
rm hello.bak
```

> `rm`으로 삭제한 파일은 보통 휴지통으로 가지 않습니다. `rm -r`이나 `rm -rf`를 실행하기 전에는 `pwd`와 삭제할 경로를 다시 확인합니다.
{: .prompt-warning }

## 파일 권한은 어떻게 읽을까

권한은 파일이나 디렉터리에 대해 사용자가 할 수 있는 일을 정합니다. `ls -l`의 권한 표시는 항목 종류 뒤에 소유자, 그룹, 그 외 사용자의 권한을 세 글자씩 보여 줍니다.

```text
-rwxr-xr-x
 │└─┬─┘└─┬─┘└─┬─┘
 │ 소유자  그룹   그 외
 └ 일반 파일 (-), 디렉터리 (d), 링크 (l)
```

| 권한 | 파일에서 | 디렉터리에서 |
| :--- | :--- | :--- |
| `r` (read) | 내용 읽기 | 목록 보기 |
| `w` (write) | 내용 수정 | 항목 만들기·삭제하기 |
| `x` (execute) | 프로그램 실행 | 안으로 이동하거나 접근하기 |

파일과 디렉터리에서 권한의 의미는 조금 다릅니다. 예를 들어 디렉터리 목록을 읽는 권한과 그 안으로 들어가는 권한은 별개입니다.

### 숫자로 권한 표현하기

숫자 방식은 `r=4`, `w=2`, `x=1`을 더해 각 사용자 묶음의 권한을 나타냅니다. 권한이 없으면 `0`입니다.

| 기호 | 계산 | 숫자 |
| :--- | :--- | :---: |
| `rwx` | 4 + 2 + 1 | 7 |
| `rw-` | 4 + 2 + 0 | 6 |
| `r-x` | 4 + 0 + 1 | 5 |
| `r--` | 4 + 0 + 0 | 4 |

따라서 `755`는 소유자에게 `rwx`, 그룹과 그 외 사용자에게 `r-x`를 뜻합니다. `644`는 소유자가 읽고 쓸 수 있고, 그룹과 그 외 사용자는 읽을 수 있다는 의미입니다.

`chmod`(**ch**ange **mod**e)는 파일이나 디렉터리의 권한을 변경합니다. 숫자 방식은 권한을 한꺼번에 지정하고, 기호 방식은 특정 권한을 더하거나 뺍니다.

```bash
chmod 755 run.sh       # 소유자 rwx, 그룹과 그 외 r-x
chmod u+x run.sh       # 소유자에게 실행 권한 추가
chmod go-w file.txt    # 그룹과 그 외의 쓰기 권한 제거
```

`sudo`는 명령을 관리자 권한으로 실행하도록 요청합니다. 시스템에 큰 영향을 줄 수 있으므로 필요한 경우에만 사용합니다. 스터디 중 접속 문제를 조치하며 확인한 `chown`은 파일이나 디렉터리의 소유자 또는 그룹을 바꾸는 명령입니다.

## 편집기로 파일 내용 바꾸기

`nano`와 `vi`(또는 `vim`)는 터미널에서 쓸 수 있는 텍스트 편집기입니다. `nano`는 화면에 단축키가 표시되어 처음 사용하기 편하고, `vi`는 모드와 키 명령을 익혀 빠르게 편집할 수 있습니다.

### nano 기본 단축키

`nano memo.txt`로 파일을 엽니다. nano 화면에서 `^` 표시는 <kbd>Ctrl</kbd>을 뜻합니다.

| 단축키 | 동작 |
| :--- | :--- |
| <kbd>Ctrl</kbd>+<kbd>O</kbd>, <kbd>Enter</kbd> | 저장하고 파일 이름 확정 |
| <kbd>Ctrl</kbd>+<kbd>X</kbd> | 종료 |
| <kbd>Ctrl</kbd>+<kbd>W</kbd> | 검색 |
| <kbd>Ctrl</kbd>+<kbd>K</kbd> | 현재 줄 잘라내기 |
| <kbd>Ctrl</kbd>+<kbd>U</kbd> | 잘라낸 내용 붙여넣기 |

### vi는 모드를 구분한다

`vi memo.txt`로 파일을 열면 일반 모드에서 시작합니다. 일반 모드에서는 글자를 입력하는 대신 이동·삭제·복사를 합니다. `i`를 눌러 입력 모드로 들어가 내용을 입력하고, `Esc`를 눌러 일반 모드로 돌아옵니다. 일반 모드에서 `:`를 누르면 저장이나 종료 명령을 입력할 수 있습니다.

| 입력 | 동작 |
| :--- | :--- |
| `i`, `a`, `o` | 커서 앞 입력, 커서 뒤 입력, 아래에 새 줄을 만들고 입력 |
| `x`, `숫자x` | 글자 하나 또는 지정한 수만큼 삭제 |
| `dd`, `숫자dd` | 한 줄 또는 지정한 수만큼 줄 삭제 |
| `yy` | 현재 줄 복사 |
| `p` | 복사한 내용을 붙여넣기 |
| `/검색어` | 검색 |
| `:set nu` | 줄 번호 표시 |
| `:w`, `:q`, `:wq`, `:q!` | 저장, 종료, 저장 후 종료, 저장하지 않고 종료 |

스터디에서는 직접 `vi`를 조작해 글자와 줄 삭제, 줄 복사와 붙여넣기, 검색, 줄 번호 표시를 연습했습니다. 마지막에는 `:wq`로 저장하고 종료했습니다. 모드가 헷갈릴 때는 `Esc`를 먼저 누르면 일반 모드로 돌아갈 수 있습니다.

> `vi`의 `dd`는 편집 중인 내용에서 줄을 지우고, 셸의 `rm 파일명`은 파일 자체를 삭제합니다. 서로 다른 동작이므로 구분해서 사용합니다.
{: .prompt-info }

## 명령을 묶어 실행하기 — 셸 스크립트

셸 스크립트는 여러 명령을 파일에 작성해 한 번에 실행하는 방법입니다. 반복 작업을 매번 입력하는 대신 스크립트로 묶을 수 있습니다. `.sh`는 셸 스크립트에 자주 붙이는 확장자입니다.

```bash
#!/bin/bash

NAME="study"
echo "안녕, $NAME"

if [ -d "$HOME/study" ]; then
  echo "study 폴더가 이미 있습니다."
else
  mkdir -p "$HOME/study"
fi

for i in 1 2 3; do
  touch "$HOME/study/day$i.txt"
done
```

첫 줄의 `#!/bin/bash`는 Bash로 이 파일을 실행하라는 표시입니다. 변수 대입에서는 `=` 양쪽에 공백을 넣지 않습니다. 조건문은 상황에 따라 명령을 나누고, 반복문은 같은 작업을 여러 번 수행합니다.

스크립트에 실행 권한을 준 뒤 `./`를 붙여 실행합니다. 셸은 `PATH`에 등록된 디렉터리에서 명령을 찾으며, 현재 디렉터리는 보통 그 목록에 포함되지 않기 때문입니다.

```bash
chmod +x hello.sh
./hello.sh
```

## SSH 키로 접속 문제 해결하기

11월 26일 스터디에서는 Vagrant 접속 오류를 해결하기 위해 Windows의 `.ssh` 폴더에서 SSH 키를 만들었습니다.

```powershell
ssh-keygen -t ed25519 -f "g2_ed25519"
```

명령을 실행하고 암호 입력 단계에서 Enter를 두 번 누르면 개인키와 공개키 파일이 만들어집니다. 개인키는 내 컴퓨터에 보관하고 공개키는 서버에 등록합니다. MobaXterm 접속 설정에는 개인키 파일을 지정했습니다. 개인키는 공유하거나 저장소에 올리지 않습니다.
